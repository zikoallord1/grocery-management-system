## تصنيف التغيير

### Bug
خطأ في تنفيذ متطلب موجود.

### Clarification
توضيح لا يغير النطاق.

### Required Change
تغيير ضروري للسلامة أو التوافق.

### New Feature
ميزة جديدة لا تدخل تلقائيا في V1.0.

## تغيير Design Baseline

أي تغيير في Architecture أو Database أو Business Rules أو Permissions أو Offline Rules يتطلب:

1. سبب واضح.
2. تحليل أثر.
3. تحديث الوثيقة.
4. تحديث الاختبارات.
5. Commit واضح.

## Definition of Done

Implemented + Tested + Integrated + Documented + Accepted
