# نظام إدارة البقالات

نظام تجاري مستقل لإدارة البقالات والعمل دون الحاجة إلى اتصال بالإنترنت.

## الهدف

بناء برنامج احترافي وسهل الاستخدام لإدارة:
- المبيعات
- المشتريات
- المخزون
- العملاء والديون
- الموردين
- المصروفات
- الصندوق والمحافظ ووسائل الدفع
- الأرباح والخسائر
- التقارير
- الباركود
- المستخدمين والصلاحيات
- سجل التدقيق والعمليات
- النسخ الاحتياطي والاستعادة
- الترخيص والتثبيت

## المبدأ الأساسي

تسجيل العملية التجارية مرة واحدة، ثم يقوم محرك الأعمال المركزي بتطبيق آثارها المرتبطة تلقائيًا دون تكرار الإدخال.

## الحالة الحالية

المرحلة الحالية هي **تثبيت النواة الخلفية والتكامل المالي وسلامة المعاملات** قبل الانتقال إلى بناء الواجهة التجارية النهائية.

تم إنجاز الأساس التالي:
- تصميم معماري ووثائق المتطلبات وقواعد العمل.
- قاعدة بيانات SQLite تعمل بوضع WAL مع تفعيل القيود وسلامة الاتصال.
- نواة المخزون وحركات الإدخال والإخراج ومنع المخزون السالب.
- المبيعات مع ربط المخزون والصندوق والعملاء.
- المشتريات مع ربط المخزون والصندوق والموردين.
- الصناديق والمحافظ ووسائل الدفع والتحويلات والمصروفات.
- محرك أعمال مركزي قائم على Business Events / Rules / Effects.
- سجل تدقيق Audit Trail للعمليات التجارية المنفذة عبر المحرك.
- مفاتيح Idempotency لمنع تكرار العمليات المالية والتشغيلية.
- اختبارات سلامة المعاملات والتراجع عند فشل العملية.
- اختبارات تلقائية عبر GitHub Actions.

## الجودة الحالية

آخر تشغيل كامل للاختبارات على GitHub Actions نجح بنجاح، بما في ذلك اختبارات النواة واختبارات التكامل الخاصة بسلامة المعاملات.

## المبدأ التطويري

لا يتم الانتقال إلى الواجهة النهائية على حساب سلامة النواة. كل وظيفة تجارية جديدة يجب أن تحافظ على:
1. عملية واحدة للمستخدم.
2. آثار مترابطة تلقائية.
3. معاملة ذرية عند الحاجة.
4. منع التكرار عبر Idempotency.
5. سجل تدقيق واضح.
6. اختبارات آلية قبل اعتماد التغيير.
