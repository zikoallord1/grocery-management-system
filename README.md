# نظام الماركت المحاسبي V1.0

نظام مكتبي عربي مستقل لإدارة البقالات، مبني ليعمل محليًا دون الحاجة إلى اتصال بالإنترنت.

## المبدأ الأساسي

يسجل المستخدم العملية التجارية مرة واحدة، ثم يتولى محرك الأعمال المركزي تطبيق آثارها المرتبطة تلقائيًا على المخزون والحسابات والصندوق وأرصدة العملاء والموردين والتقارير، مع منع التكرار وسلامة المعاملة.

## المكونات المنجزة

- قاعدة بيانات SQLite بوضع WAL وقيود سلامة مفعلة.
- نواة المخزون ومنع المخزون السالب ومبدأ التكلفة المتوسطة المرجحة.
- المبيعات مع ربط المخزون والصندوق والعملاء.
- المشتريات مع ربط المخزون والصندوق والموردين.
- الصناديق والمحافظ ووسائل الدفع والمصروفات.
- محرك Business Events / Rules / Effects مركزي.
- سجل تدقيق Audit Trail للعمليات التجارية.
- مفاتيح Idempotency لمنع تكرار العمليات.
- اختبارات سلامة المعاملات والتراجع عند الفشل.
- طبقة تقارير وملخصات مالية وتشغيلية.
- واجهة سطح مكتب عربية RTL مبنية بـ PySide6.
- لوحة رئيسية مرتبطة مباشرة ببيانات التقارير.
- تنقل موحد بين المبيعات والمشتريات والمخزون والعملاء والموردين والمصروفات والتقارير.
- هوية البرنامج وبيانات التواصل مركزية.
- زر اتصال يفتح رقم الدعم، وزر واتساب يفتح المحادثة مباشرة.
- اختبار تشغيل الواجهة في وضع offscreen.
- بناء تلقائي لنسخة Windows executable عبر GitHub Actions ورفعها كـ Artifact.
- وحدات وعبوات معرفة لكل صنف بمعامل تحويل مستقل، مع حفظ لقطة الوحدة داخل حركة البيع والشراء.
- قارئ باركود بالكاميرا للواجهة مع دعم المسح المتكرر.
- إغلاق يومي تلقائي وإنشاء نسخة احتياطية يومية.
- **نظام تراخيص محلي موقّع تشفيريًا** مع فترة تجريبية، ربط الترخيص بتثبيت العميل، والتحقق من تاريخ الانتهاء وسلامة الملف.
- **برنامج مستقل لإنشاء التراخيص** `license_manager.py` مخصص لمالك المنتج.

## نظام التراخيص

يتكون النظام من جزأين:

1. **داخل نسخة العميل:** إنشاء معرّف تثبيت محلي، فترة تجريبية، قراءة ملف الترخيص، التحقق من التوقيع، ربط الترخيص بالتثبيت، والتحقق من تاريخ الانتهاء.
2. **مدير التراخيص:** أداة مستقلة لإصدار تراخيص موقعة باستخدام مفتاح إصدار خاص، وتحديد العميل والمنشأة ونوع الترخيص وتاريخ الانتهاء، وتصدير مفتاح التحقق العام.

يستخدم الإصدار توقيع **Ed25519**؛ المفتاح الخاص يبقى لدى مالك البرنامج ولا يُضمّن في نسخة العميل. مفتاح التحقق العام هو المفتاح الذي توضعه النسخة التجارية لدى العميل.

لتشغيل مدير التراخيص من المصدر:

```powershell
pip install -r backend/requirements.txt
python license_manager.py
```

سيتم إنشاء مفاتيح سلطة الإصدار محليًا في:

`%USERPROFILE%\\.grocery_management_license_authority`

**تنبيه أمني:** ملف `license_private_key.pem` هو سر الإصدار ويجب عدم مشاركته أو رفعه إلى المستودع أو تضمينه داخل البرنامج التجاري.

## ملاحظة الجودة

لا تعتبر أي ميزة تجارية مكتملة بمجرد ظهورها في الواجهة؛ يجب أن تكون مرتبطة بالنواة، ذرية عند الحاجة، قابلة للتدقيق، ومغطاة باختبار آلي قبل اعتمادها.

## حدود الإصدار الحالي

النسخة الحالية تطبيق مكتبي محلي؛ لا توجد طبقة HTTP أو مزامنة خادم مكتملة. العمليات التجارية المحلية تمر بمحرك الأعمال وتُسجل في سجل التدقيق، وتتوفر طبقة Backend للتحقق من الصلاحيات والنطاق وفصل المهام عند استدعائها من خدمة موثوقة. ما زال ربط كل شاشة بالهوية والصلاحية من Backend، ومصفوفة Sync V3.12 والترحيل `SYNCED`/`POSTED`، ومساعد الذكاء الاصطناعي الفعلي، خارج البنية الحالية ويجب عدم اعتبارها منجزة بمجرد وجود عناصر واجهة.

أضيفت في النواة خدمة `SyncService` محلية تطبق حالات V3.12، ترتيب الاستلام بالخادم، مفاتيح `source_transaction_id` و`idempotency_key`، التسوية قبل الترحيل، وفصل `SYNCED` عن `POSTED` وإنشاء عملية عكس دون حذف الأصل. كما أضيف `IdentityContext` لتمرير هوية جلسة الدخول إلى Backend، ومساعد محلي للقراءة والتشخيص فقط. هذه الطبقات لا تدّعي أنها مزامنة شبكة أو نموذج ذكاء اصطناعي خارجي؛ يلزم تنفيذ ناقل الخادم وسياسة الاعتماد التجارية قبل تحويلها إلى مزامنة رسمية.
